## 1. 目标与边界

本任务体系要交付可实际使用的 SRFlow 核心，而不是把 Compile Probe 直接搬进正式工程。核心以异步 Rust 实现，保持一个 crate、清晰分层：`core` 承载执行模型，可选扩展（首先考虑 `llm`）位于核心之外的模块，并由 Cargo feature 控制。

已确定的接口方向：普通使用者实现 Node，框架将 Node 接入统一的 Executable 执行入口；只有新增执行语义时才直接实现 Executable。Node 不负责启动其他 SRFlow Executable。Flow 与控制型 Executable 调用子对象时必须重新经过 Runtime。

本轮核心范围包括 Runtime、Executable、Node、Flow、Ref、Binding、Retry、Match、Each、Iter、SubFlow，以及业务正常结果与执行错误的边界。Flow、Each、Iter 默认保持顺序执行；使用 async Rust 不意味着自动并发。

本轮不加入日志、Trace、持久化、恢复、动态 Graph DSL、自动并行、技术故障重试或隐藏在 Runtime 中的控制原语。可选 LLM 能力和 crates.io 发布分别设任务，不作为核心模型成立的前提。

SRFlow 以独立 crate 对外提供，因此使用文档与可运行示例是交付内容，不是发布前才一次性补写的附属工作。每项任务在引入公共能力时同步编写面向使用者的 Rustdoc 和对应的最小用法；T08 负责整理完整示例路径，T11 负责发布前文档检查。实现内部的注释应解释不变量与不明显的取舍，不以逐行重复代码代替说明。

## 3. 共通验收原则

- 正常路径与边界／失败路径都要有验证。需要由类型系统拒绝的错误连接，应采用编译失败测试或同等可复核证据；运行时归属和执行错误应验证失败发生的位置及后续 child 未被执行。
- 所有组合型 Executable 的 child 调用都必须重新经过 Runtime；异步实现不得改变 Flow、Each、Iter 的既定顺序语义。
- Error 不自动意味着重试或回滚；已经发生的外部副作用也不因后续执行失败而被宣称撤销。失败的组合型 Executable 不向父级暴露部分正常 Output。
- 公共接口从独立使用者的角度验证，不以同 crate 内部测试能访问私有实现作为 API 可用性的证据。
- 新增公共类型、方法或 feature 时，同步写明用途、输入输出或返回值、关键边界、错误行为及一个尽量可运行的用法；在 docs.rs 面向使用者展示的 Rustdoc 应足够独立可读，不依赖阅读实现源码。
- `examples/` 至少覆盖：最小 Node 与 Runtime、基础 Flow 与 Ref 复用、多 Ref Binding、SubFlow、Retry、Match、Each、Iter，以及一个嵌套组合示例。可合并相近主题，但不得只用一个庞大示例代替循序渐进的说明。核心 examples 应可离线编译和运行；`llm` 示例在 T10 增补，并清楚标明所需 feature 与外部服务边界。
- 任务验收记录应说明对应的设计章节、通过的验证、未定的实现策略与偏差；发现规范性冲突时先评审设计，不在实现中静默改写语义。

### G1 独立验收记录（2026-09-30）

**结论：G1 PASS。** T01、T02、T03 已分别完成实现与复审；本次另行检查三项能力的组合边界，而非把三项任务的状态机械相加：

- 异步 `Executable`／`Node` 具有强类型 Input／Output，`Runtime::execute` 是统一入口；组合型 Executable 与 Flow 内部 child 均重新经过 Runtime，普通 Node 不获得编排用 Runtime。
- Flow 顺序执行异构 child；`Ref<T>` 只读、可复用且属于特定 Flow，外来 Ref 在构建期拒绝；SubFlow 只经 Input／Output 与父级交换数据，每次调用的值存储独立。
- Binding 能在统一 `then(executable, binding)` 入口下完成整值复用／消费、字段投影、2～8 元 tuple、命名及嵌套装配；类型错接在编译期拒绝，多来源读取登记失败保持原子性，投影不强迫复制整个根。

依据 T01～T03 的验收记录、公开 API／执行路径审查及最近一次独立复跑：61 项目标测试、25 项文档测试、六个离线示例、格式／Clippy／文档构建均通过。**保留边界：**T03 的两个 `#[doc(hidden)]` 公开构造入口仍可绕过结构性约定，已作为已知漏洞写入 Rustdoc 与 T03 验收记录；G1 通过不等于该风险被类型系统封死。Rust 1.85 的 MSRV 实测留给发布前验收。G1 只解锁控制型 Executable 的任务书审定与后续逐项实现；不自动授权 T04，也不关闭 G2。

## 5. 执行与仓库约束

- 本仓库独立维护文档与代码；不得把冻结的旧 SRF v0.1 工程当作新核心改造对象。
- Compile Probe 是可行性证据，不是正式实现模板；尤其不直接固化其 Clone、类型擦除、Binding 宏和内部值存储选择。
- 自动测试使用 Fake Node 或本地替身，不依赖 SES 仓库、真实模型、外部网络或用户正式业务数据。
- 每项交付都应记录改动范围、验证结果、与设计文档的对应关系，以及尚未解决的实现权衡。
- 本任务总览及后续任务文档可以提交到 SRFlow 远程仓库；提交、推送、打标签和 crates.io 发布分别是明确的操作，不因仓库已有远程地址而自动发生。
